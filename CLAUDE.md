# OBS Config Loader: project handoff

Read this first, then `PROJECT_BRIEF.md`. This file is the running state and decision log: update it whenever a decision or the state changes.

## Engine
This app is pinned to TurboNZL/turboengine (see `.turboengine.json`). The engine is a **reference, not a dependency**: copy working modules from its `modules/` rather than inventing new ones (updates, release naming, theme picker, window chrome, settings layout, guides). If you improve a module here, say so in the session log so it can be ported back.

## User preferences (how to work with them)
- Don't waste their usage. Fact-check and double-check yourself; use web search liberally.
- They write casually; reply in normal capitalised prose.
- Verify against real runs, not only unit tests.
- This is a **public, general tool**: never hard-code the owner's own setups (Flatpak OBS + Multi RTMP, the Prismalite setup, Aitum). Those are only examples of what it must handle.
- A merged PR cannot take new work: restart the branch from main for follow-up changes.

A file in `cloud.stored` is not uploaded to GitHub and counts as kept elsewhere. Un-ticking never deletes the object. |

## Hard-won gotchas
- **A real stream key and a Discord bot token were committed to the owner's preset (2026-11-09, found by reading their `obs-config-prismalite-obs` repo):** (1) Multi RTMP's `obs-multi-rtmp.json` starts with a UTF-8 BOM, `JSON.parse` refused it, and a profile file that cannot be parsed fell through to a RAW copy: the key went in unscrubbed. `readJson` now strips the BOM, and a `.json` that still cannot be read is left out with a warning, never copied; (2) profile spare copies (`*.bak`, `.old`, `~`) were copied raw with the same secrets: never kept (`BACKUP_FILE`); (3) a script folder kept every `.txt`, including the project's own saved setup code with the bot token (`prismalite-preset.txt`) and OBS's own `lib/obs-scripting/obspython.py`: the walk now honours the folder's `.gitignore` (`makeIgnore`) and drops any text/data file that looks like `TOKEN=value` / `"password": "…"` (`looksSecret`, `DATA_FILE`; code files are not scanned, they say "token" as a word); other profile files that look like secrets are left out too. Rule: **a file whose contents cannot be checked is never copied as it is.** Tests: `test/safety.test.ts`. The owner's existing commit still has the old values: they must rotate the keys (stream key, bot token, OBS password, chat-feed token) and start a fresh GitHub copy. Not done: a "check this preset for secrets" button, scrubbing token-carrying browser-source URLs.
- **Windows CI, test side (2026-11-09):** a fake-Linux importer writes `/` paths while the test's own `nodePath.join` gives `\` on Windows: compare through `fwd()` (test/helpers.ts), never `toBe(nodePath.join(...))` on a produced path. Five such assertions had been red on the Windows runner since 2026-11-03 and were unseen because the whole `main` run was red for other reasons.
- **A preset must not ask for attention over nothing (2026-11-05, owner: "still asks me after I do it", the line read "Copy of the file Lo… only on this computer"):** (1) the preset's own copy of a big file (`local/media/…`) was judged stale by a newer DATE alone, so a sync tool/player touching the file made "OBS has changes" come back after every save. `sameFileContent` now compares bytes when sizes match (once per date pair, remembered; files over 1 GB still go by date), and the dry run never lists `local/media/*` (the next real save refreshes them quietly); (2) `pendingForObs` counted another system's entry in `platforms.json` and `assets.lock.json` as "updates for this OBS": now only this system's entry counts. Regression tests: `test/attention.test.ts`. Reproduced in a scratch test before fixing, not on the owner's own preset (not visible from the cloud session).
- **Speed (2026-11-04, owner's Windows report: slow boot, Presets tab overwhelmed):** the boot page (Home) and every preset tile each ran a full OBS-versus-preset diff (with line-by-line preview), a `git fetch`, sizes of every file, and a refresh of ALL presets and OBS installs when the fetch finished: the work grew with presets squared and ran on the main process at once. Now: heavy reads go through `heavy()` (one at a time, yielding between) and `online()` (two lanes), `memoised()` shares/reuses an answer for 3-60 s and is cleared before and after any IPC that is not in `READ_ONLY` (**add every new read-only channel there**, and clear by calling any mutating one when a test changes files behind the app's back), the preview diff is read only when "See what changed" is opened (`repos:live` 3rd arg), a fetch patches that one tile (`patch`) instead of reloading everything, Home fills in one preset at a time, `repoStatus` runs its independent git calls together, `git --version` is cached for a minute. NOT measured on a real Windows machine (none here), and the heavy work still runs on the main process between yields (a worker thread would be the next step).
- **`git add` with a path that does not exist fails the whole command** (`applyCloudSettings` used to list `media` unconditionally; harmless only because its other changes were staged by `rm --cached`). Filter pathspecs by existence.
- **Files inside a script folder (2026-11-03):** a source's file inside a script folder (Prismalite's `images/*.png`) was written relative to the folder variable but never copied: only code files were kept and `images/` was skipped, so a fresh machine had none. `Collector.noteProjectFile` now remembers every file a source points at inside a project and `collectProjects` keeps it (size cap = the big-file limit, over it a warning) under `scripts/projects/<VAR>/`. Import allows `PROJECT_KEEP` (code, pictures, sounds, data; never programs). Checked on the real rendered Prismalite config: 11 of 11 images. Anything under a script folder that no source points at is still not copied unless it is code.
- **Local part of a preset / upload rules (2026-11-03):** (1) `captureLive` writes `info/exclude` BEFORE `repoStatus`, otherwise `local/` shows up as dirty; (2) a part newly kept off the upload may still be tracked in the commit OBS last matched: the scratch checkout runs `git rm` of those paths and commits that first, so the live commit and HEAD agree (otherwise a modify/delete conflict) and `stopped` forces the merge even when nothing else changed; (3) a part uploaded again is `git add -f`ed from the on-disk copy before the status check (`settings.kept` remembers what was kept out, because a dry run rewrites `info/exclude` too; `writeLocalSettings` carries `kept` over); (4) `readBundleDir` leaves out collections/profiles whose files are missing (a copy from GitHub lacks the kept-back parts) except with `{ keepMissing: true }`, which anything that writes the manifest back must use; (5) anything from a manifest that becomes a path goes through `safeSegment` (a cloned preset is untrusted); (6) `sha256File` is cached by path+size+mtime (hashing 4 GB videos on every status check was the slowest thing in the app); (7) a script folder's code files are kept in the preset (`manifest.projects`, `scripts/projects/<VAR>/…`), and importing writes them only into a new/empty/same-project folder.
- **Prismalite OBS check (2026-11-02, real files, `~/prismaliteobs` rendered like its own `render` does, then saved and applied):** found and fixed (generically, nothing Prismalite-specific is in the code): (1) its OBS script finds `switcher.py`/`venv`/the audio FIFO by `__file__`, and we copied the script alone into `media/` (broken) -> script folders ("projects", `Collector.addScript`, `SCRIPT_FOLDER`, `Variable.mustContain`); (2) FIFO and music paths came out empty -> everything under the script folder stays relative to it, and path variables with no suggested place default to the original path; (3) its tooling works on `profiles/Prismalite_Profile` and `scenes/Prismalite_Scenes.json` while the profile is *shown* as `Prismalite_Profile_2026_sep_22` -> `dirName`/`fileName` keep OBS's own names; (4) an empty remote-control password was written back -> not written without one. After the fixes the applied scene collection is identical to the original (JSON-normalised) and so are all profile files, from the preset and from a file with keys; OBS opens with the same profile/collection; remote control restored. NOT translated: Prismalite's Windows build feeds audio over UDP not a FIFO (the `Call FIFO` source keeps the same path form on Windows); OBS's Python path (`[Python]` in OBS settings) is not carried (OBS-level, not part of a setup). The scratch test is at `scratchpad/prismalite-roundtrip.local.test.ts` (not committed: it names a private repo); the generic cases live in `test/projects.test.ts`.
- **Read-only git checks must use `--no-optional-locks`** (`git status` otherwise rewrites the index and collides with a save running at the same moment: showed up as `index.lock: File exists`).
- **"Big files this computer still needs" for files that are right here (2026-11-02):** presets hold only placeholders for media, and locations were only remembered when the person typed them. Now remembered from three places: import (`report.assetLocations`, merged), every save (`onAsset` callback in export: where each file really is), and `locateExtracted` (`<cfg>/obs-config-loader/<setup id>/media/<asset>/<file>`, where a setup file's own copies are put). `locations:save` MERGES (a screen that knows less must not wipe what import learned). `e2e.cjs` fails if the preset asks for files it already has (checked: it does fail with the fix off).
- **Local and online disagree:** ahead/behind is only as fresh as the last `fetch` (`fetchRepo` first). Diverged = both ahead and behind (or no shared history): show dates of each side's newest save and offer Combine (pull; retries with `--allow-unrelated-histories`), Keep mine (`push --force-with-lease`: refuses if someone pushed since we looked), Use the online one (`useOnlineVersion`: `reset --hard`, old tip kept on branch `before-online-<time>`; refuses with unsaved changes). Never a plain `--force`.
- **Which profile OBS opens with (2026-11-02, from OBS source):** OBS 31+ reads `Basic/Profile`, `ProfileDir`, `SceneCollection*` from `user.ini` (global.ini = app facts like `General/LastVersion`). We only wrote global.ini, so a Windows OBS opened "Untitled". `userconfig.ts` reads user.ini first and writes both files that exist (user.ini alone for a never-run OBS: a version-less global.ini makes a new OBS try to migrate it). The e2e fixtures use user.ini.
- **Encoders:** an encoder id the target OBS lacks leaves the Settings encoder boxes empty and OK disabled. `encoders.ts` swaps unavailable ones for `obs_x264`/`ffmpeg_aac`, trusting OBS's `plugin_manager/modules.json` `encoders` lists only when they contain both of those (otherwise only ids that cannot exist on that system). Profile encoders and audio devices are kept per system in `profiles/<id>/platforms.json` (`profilevariants.ts`), canonical lines frozen at the first save so systems never fight.
- A file made from an online preset carries `manifest.repository.url` (no password); opening it offers the latest from there and keeps it as a preset by default (`bundle:latest`, `repos:fromBundle`). `fetchRepo` runs before "N to download" is shown, because ahead/behind is only as fresh as the last fetch.
- **Aitum Stream Suite (2026-11-02, from its source):** module `aitum-stream-suite`, per-profile `aitum.json` (canvases, outputs incl. stream keys, dock layout), source id `component_source`; it is a different plugin from Aitum Multistream (`aitum-multistream`). Plugins that add only docks leave no source id in a scene, so detection needs a file hint (`FILE_HINTS`). Plugins can be Linux-only (`PluginRef.platforms`): on other systems they are `not-needed`, never "missing". Plugins NEVER block a load (only OBS running, or nothing selected, does).
- Windows: do not start PowerShell on every refresh of the import summary (slow). OBS's `plugin_manager/modules.json` is read first and PowerShell only runs when it does not exist; versions are cached per OBS for a minute in main. Arguments after `-Command` are glued onto the command (not `$args`): pass folders through the environment.
- **PipeWire capture ids (2026-11-02):** OBS 30.2+ has ONE `pipewire-screen-capture-source` (window or display, chosen in the system dialog; OBS's own Windows-to-Linux importer maps window/game capture to it); older OBS has `pipewire-window-capture-source` and `pipewire-desktop-capture-source` (the app picks by the target OBS version when known). Windows window/game capture have `capture_audio`; the audio is a private child source that is NOT saved in the collection, so translation must add a real source. `wasapi_process_output_capture` = Application Audio Capture.
- **A save must read "what to leave out" from the preset's CURRENT files**, not the commit OBS last matched (saves are measured from that older commit): otherwise changing it never takes effect (found by the e2e, fixed in `captureLive`).
- Playwright tips for this UI: a notice stays on the page after a save, so wait for text unique to the new save (the file path); `isDisabled()` ignores `<option>`; controlled checkboxes only change after an async call, so `click()` not `check()`; after a rename the app's list of OBS layouts must be re-read (`refreshInstalls`).
- **Plugins (2026-11-02):** OBS keeps `<settings folder>/plugin_manager/modules.json` (`module_name`, `version`, `enabled`, `sources`...): it is the source for "is this plugin installed / switched off / which version", on every install kind, independent of where files are. A plugin only has a version there if it exports `obs_module_version`; **PipeWire Audio Capture does not** (checked in its 1.2.2 build: only `obs_module_description`), so its version is always blank: say so, never invent one. Its module is `linux-pipewire-audio` (flat `linux-pipewire-audio/linux-pipewire-audio.so` in OBS 33+). OBS 33+ user plugins: `~/.local/share/obs-studio/plugins` (Flatpak: `~/.var/app/<id>/data/obs-studio/plugins`); 28-32: `<settings folder>/plugins/<name>/bin/64bit/`. Flatpak plugin extensions are `runtime/` refs, not `app/`, and sit deep (`<ext>/<arch>/<branch>/<commit>/files/lib/obs-plugins`).
- **Saving follows OBS** (no name filter, found out the hard way: a rename wiped the repo). `writeLiveInto` refuses to save an empty OBS over a preset that has content.
