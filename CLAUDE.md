# OBS Config Loader: project handoff

Read this first, then `PROJECT_BRIEF.md`. This file is the running state and decision log: update it whenever a decision or the state changes.

## Engine
This app is pinned to TurboNZL/turboengine (see `.turboengine.json`). The engine is a **reference, not a dependency**: copy working modules from its `modules/` rather than inventing new ones (updates, release naming, theme picker, window chrome, settings layout, guides). If you improve a module here, say so in the session log so it can be ported back.

## User preferences (how to work with them)
- Don't waste their usage. Fact-check and double-check yourself; use web search liberally.
- They write casually; reply in normal capitalised prose.
- Verify against real runs, not only unit tests.
- This is a **public, general tool**: never hard-code the owner's own setups (Flatpak OBS + Multi RTMP, the Prismalite setup, Aitum). Those are only examples of what it must handle.
- A merged PR cannot take new work: restart the branch from main for follow-up changes.

## Decisions made (don't re-ask)
| Topic | Decision |
|---|---|
| Repo | `TurboNZL/obs-config-loader` |
| Stack | TurboEngine: Electron + React + turbothemes; core logic in a plain TypeScript package |
| First milestone | Format spec + cross-platform core (detect, export, import, remap); minimal UI |
| Bundle | `.obsbundle` = zip (plain `.zip` accepted) + unzipped directory form for git. Spec: `docs/FORMAT.md` |
| Plugins | Never bundled; reported with install instructions |
| Plain words | The app talks to streamers, not developers. Never show: bundle, collection, profile, placeholder, dry run, variable/secret names (STREAM_KEY_2), merge, commit, repo(sitory), import/export. Use: setup file, scenes ("scene layouts"), output settings, big files, stream key + the service/target name it belongs to, backup, load/save. State once what a thing is called in OBS ("OBS calls these Scene Collections"). Each screen leads with what will happen in one sentence; file lists and technical detail live behind "Show details". Warnings use `Message` (tinted + coloured edge: themes override borders, so border colour alone is invisible). When wording changes, update the e2e scripts: they select by visible text. |
| Stream keys | Left out by default. Optional "Include my stream keys" on the Save screen: `containsSecrets` + `warning` in the manifest, `READ-ME-FIRST-CONTAINS-STREAM-KEYS.txt` in the zip, `(CONTAINS STREAM KEYS)` in the suggested file name, red banner on load. NEVER allowed in the git folder form (`writeBundleDir` throws). A secret `value` is only honoured when `containsSecrets` is true. On load: typed > from the file > already in OBS. |
| Presets | The app's unit is a **preset** = one saved setup folder (git inside, always, for history). New presets live in the app's own folder (`<Documents>/OBS Config Loader/Presets/<name>`, changeable in **Settings**, existing presets stay put). "Back up online" is a per-preset switch (publishes to GitHub, then every save uploads; off just removes the remote). "Export to a file" is a button on each preset. GitHub sign-in, git install and the keys/folder settings live on the **Settings** page, not on Presets. Pages: Home, Presets, OBS on this computer, Settings, Help, Look, About; the old Save/Load pages are reached from Presets ("Save a file straight from OBS…", "Open a setup file…"). |
| Stream keys (presets) | Never in a preset folder or online. After each save the app remembers the keys of that OBS on this computer only, encrypted with `safeStorage` (setting "Remember my stream keys", default on; nothing is stored without a keychain), keyed by the preset's manifest id, same store the Load page already uses. Export-to-file can include them via `attachSecrets`. |
| Renames | Done in the app on a preset (preset / scene layout / output settings / scene or source). Always also done in the linked OBS when it has the same thing and is closed, after first saving OBS into the preset: otherwise the next save would re-add the old name (save follows OBS, it no longer filters by names). |
| Versions | `savedWithObs` and `plugins[].version` only ever go UP (newest any computer saved with), so two computers never fight over them. Never record anything else derived from one machine. |
| GUI first | Anything a user would otherwise do on the command line (git init/clone/remote, creating a repo on GitHub, resolving a conflict, installing git) is done in the app. A command is only ever shown as a copyable last-resort fallback. |
| GitHub | Sign-in is a personal access token pasted in the app (a link opens GitHub's token page with the permission pre-ticked); stored with `safeStorage`, memory-only when there is no keychain; handed to git through `GIT_CONFIG_*` env (never argv, `.git/config` or the remote URL). Other hosts use the user's own git credentials. |

Re-run it with `xvfb-run -a node apps/desktop/e2e/e2e.cjs` after `pnpm --filter @obs-config-loader/desktop build` (needs playwright and the Electron binary).

- Separate OBS instances: core unit tests (folders per install kind, launch commands, seeding without plugins, which-OBS-is-running from a fake /proc) + `apps/desktop/e2e/e2e-instances.cjs` through the screens with a fake `flatpak` on PATH: make, start, own-settings check, running shown for the instance only, failure paths (cannot start / started but ignored the setting), remove.

## Hard-won gotchas
- **Plugins (2026-11-02):** OBS keeps `<settings folder>/plugin_manager/modules.json` (`module_name`, `version`, `enabled`, `sources`...): it is the source for "is this plugin installed / switched off / which version", on every install kind, independent of where files are. A plugin only has a version there if it exports `obs_module_version`; **PipeWire Audio Capture does not** (checked in its 1.2.2 build: only `obs_module_description`), so its version is always blank: say so, never invent one. Its module is `linux-pipewire-audio` (flat `linux-pipewire-audio/linux-pipewire-audio.so` in OBS 33+). OBS 33+ user plugins: `~/.local/share/obs-studio/plugins` (Flatpak: `~/.var/app/<id>/data/obs-studio/plugins`); 28-32: `<settings folder>/plugins/<name>/bin/64bit/`. Flatpak plugin extensions are `runtime/` refs, not `app/`, and sit deep (`<ext>/<arch>/<branch>/<commit>/files/lib/obs-plugins`).
- **Saving follows OBS** (no name filter, found out the hard way: a rename wiped the repo). `writeLiveInto` refuses to save an empty OBS over a preset that has content.
- OBS scripts are assets with `role: 'script'` stored under `scripts/` (kept in git, up to 1 MB); WebSocket settings are `global/obs-websocket.json` with the password as a secret variable. OBS still needs Python configured by the user; the app only says so.
- Untested on real machines: Windows (PowerShell file version) and macOS (Info.plist) plugin version probes, the in-app rename against a real OBS, OBS `LastVersion` parsing against a real `global.ini` (parsed per OBS's source, range-checked so a wrong guess shows nothing rather than something wrong).
- OBS rewrites its config on exit: importing while OBS runs is lost. Import is blocked when the caller says OBS runs.
- Source ids and config paths were checked against OBS's own source (`plugins/*`, `frontend/obs-main.cpp`, `libobs/util/platform-nix.c`) on 2026-10-29. obsproject.com is not reachable from cloud sessions; GitHub is.
- Linux OBS honours `XDG_CONFIG_HOME` and `--multi`, so a second instance with its own config is possible natively. Whether Flatpak passes `--env=XDG_CONFIG_HOME` through is UNTESTED (needs a real machine).
- Portable: Windows = `<root>/config/obs-studio`, switched on by `--portable` or `portable_mode.txt` in `<root>`; Linux only if OBS was built with `ENABLE_PORTABLE_CONFIG` (then `<root>/config/obs-studio`, started from `bin/`).
- Multi RTMP keeps its targets AND stream keys in `obs-multi-rtmp.json` inside the profile folder. All profile JSON is secret-scrubbed, not just `service.json`.
- PipeWire window/screen/desktop capture is built into OBS (ids `pipewire-*-capture-source`); the third-party plugin is PipeWire *audio* capture (`pipewire_audio_*_capture`).
- OBS appends `_vN` to versioned ids (`text_ft2_source_v2`); strip before matching.
- A substituted source loses its settings on purpose (devices/windows do not translate); a source with no equivalent keeps its id and settings and its scene items are hidden.

- Electron 39+/40+ could not be installed in the cloud sandbox (`@electron-internal/extract-zip` 404 on the npm mirror), so `electron` is pinned to 38. Revisit on a normal machine. Electron's binary needs `--no-sandbox` when run as root, and the postinstall is skipped by pnpm: run `node node_modules/electron/install.js` once.
- pnpm cannot fetch the `themes/` sub-folder of turboengine in the cloud sandbox (codeload 403), hence the vendored copy.
- The theme updater's network call fails with a certificate error inside the sandbox; harmless, the built-in themes are used.
- Secrets typed in the Import page are remembered only when `safeStorage` encryption is available; otherwise they are never written.

- Git design: live edits are committed in a scratch `git worktree` on the last-synced commit (local ref `refs/obs-config-loader/synced/<install>`), then merged into HEAD. Do not simplify this to "write OBS over the working tree": it silently drops repo-side edits. `revision`/`exportedAt` stay frozen in the directory form so merges never conflict on them. Git is the user's own `git` (no bundled libgit); prompts are disabled (`GIT_TERMINAL_PROMPT=0`), so credentials must already work non-interactively.
- Per-platform variants (`variants.ts`, `collections/<id>.platforms.json`): one version of each capture source per OS; saving on an OS only writes its own entries. The collection file keeps the first saver's version (`preservePlatformSources`). A manifest field derived from one machine's live state makes every machine's save differ and the app report "OBS has changes" forever: `plugins`/`platformMap` are derived by `deriveManifestFields` from the files, `source`/`generator` are frozen after the first save. Test a two-machine round trip whenever the manifest or capture changes.

- **CI lessons (2026-11-01, all four jobs were red on `main`):** (1) `pnpm/action-setup` must not get `version:` when `package.json` has `packageManager` (it is in the engine's release-pipeline notes; read them). (2) `.gitignore` had `dist/`, which silently excluded `vendor/turbothemes/dist`: it worked on the dev machine and failed on every fresh clone. Always run `scripts/ci-local.sh` (fresh clone) before pushing. (3) Git prints repo paths as `C:/Users/RUNNER~1/...`; compare folders with `samePath()`, never string equality (it made every repo look like "not a repo" on Windows).
- **Windows CI**: the core tests run on a real Windows runner; fake-Linux tests with real files must not assert on path separators.
- Importing without typing a secret keeps the value already in OBS (`keptSecrets`); it must never blank a stream key.
- Workflow runs on PRs opened by the Actions bot wait for approval (`action_required`); `workflow_dispatch` on check.yml lets a run be started without that.

- electron-builder: keep only run-time modules in `dependencies` (just `electron-updater`); everything else is bundled by esbuild/Vite and lives in `devDependencies`, or the installer swells. `-c.electronDist=node_modules/electron/dist -c.electronVersion=<v>` lets it package offline.
- The release workflow sets the desktop package version from the tag (`npm pkg set version`); the dpkg name is `deb.packageName` (= `DEB_PACKAGE` in updater.ts, which the updater uses to confirm an install).
- Repo settings the release needs (the user does these): Actions enabled, Workflow permissions = Read and write, and "Allow GitHub Actions to create and approve pull requests".

- **Instances**: only where OBS reads `XDG_CONFIG_HOME`/`XDG_DATA_HOME` (Linux system package, Flatpak). Windows/macOS ask the OS for the folder, so the app says so and points to portable copies. Verifying a start means looking for something OBS writes *at launch* (a new `logs/` file or a newer `global.ini`), never "the folder exists": seeded settings make the folder exist before OBS ever runs (that was a real bug). "Is OBS running" is per settings folder on Linux (`processes.ts`, reads /proc environ), so a separate OBS does not block imports into the main one.

- **Engine port-back candidates** (say so in the engine's session log): the `load` emblem (`branding/emblems/load.json`, colour `#2fd27a`) for `logos`; `gen-icons.mjs` needs `PLAYWRIGHT_MODULE=<…/playwright/index.mjs>` when playwright is not resolvable from the app (document in the module); the release-pipeline `package` job (build real installers on all three OS on every PR, no publishing) and a `workflow_dispatch` on the check workflow (PR runs from the Actions bot wait for approval); `pnpm e2e` + the `e2e` CI job pattern (Electron under Xvfb with Playwright `_electron`, stubbed dialogs); `deriveManifestFields`-style "derive, never copy from one machine" rule for any shared file two machines write.

- Stream keys opt-in: tested in `test/streamkeys.test.ts` (off by default and absent from every byte of the zip; labels like "Stream key for Twitch" / "Multiple RTMP outputs: “YouTube”"; README inside the zip; refused for git folders; stray values ignored; typed beats file beats existing) and `e2e-keys.cjs` (file name mark, red warnings, load with and without keys, existing key kept).
